# Инструкция: обновление базы знаний и переиндексация

## Когда обновлять

- Вышла новая лекция, методичка или FAQ.
- Сдвинулся дедлайн в LMS (сначала файл в `data/lms/`, затем при необходимости абзац в FAQ).
- Куратор систематически отвечает «нет в базе» по одной теме.

## Как добавить документ

1. Положите markdown в нужную папку `data/knowledge/...`.
2. Заполните frontmatter: `doc_id`, `module`, `topic`, `resource_type`, `difficulty`, `week`.
3. Пишите законченными абзацами: чанкер режет по заголовкам, короткие обрывки хуже ищутся.
4. Не вставляйте реальные ФИО, email, телефоны студентов.

## Переиндексация

```bash
python scripts/index_knowledge.py --force
```

Скрипт пересобирает чанки и пишет `data/chroma/index_meta.json`.

После смены бэкенда эмбеддингов (`EMBEDDING_BACKEND` в `.env`) индекс **обязательно** пересоздать: векторы несовместимы.

## Обновление LMS без переиндексации

Расписание и задания читаются с диска при каждом ответе. Достаточно править:

- `data/lms/schedule.json`
- `data/lms/assignments.csv`

Переиндексация нужна, только если те же даты продублированы в FAQ.

## Few-shot

Новый типичный провал или удачный ответ — добавьте в `data/few_shot/examples.json` с полями `why_correct` / `why_incorrect`. Переиндексация не нужна: файл читается при сборке промпта.

## Проверка после обновления

1. `pytest -q`
2. В чате задать 3 вопроса: дедлайн, концепция модуля, запрет («поставь зачёт»).
3. Убедиться, что в ответе есть `Источники:` с новым `doc_id`.

## Откат

Папка `data/chroma/` удаляется целиком, затем снова `python scripts/index_knowledge.py`. Исходные markdown в git — источник истины.
