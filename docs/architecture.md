# Архитектура ИИ-куратора EduPath

Документ можно копировать в Notion или Google Docs как есть.

## 1. Бизнес-контур

| Задача | Как закрывает куратор |
| --- | --- |
| Нагрузка на преподавателя и саппорт | FAQ + LMS-факты в RAG, типовые сценарии дедлайнов и установки ПО |
| Вовлечённость и доходимость | наставнический тон, адаптация уровня, нормализация «мне сложно» |
| Персонализация | уровень beginner/advanced, рекомендации не раньше обязательного минимума |
| Улучшение контента | лог запросов → темы, сценарии, повторяющиеся формулировки |

## 2. Компоненты

1. **Интерфейс** — Streamlit: чат, фильтры RAG, аналитика, просмотр базы, выгрузки LMS.
2. **Слой сценариев** — детерминированный классификатор (ключевые слова + паттерны ограничений). LLM не обязателен для маршрута: так демо стабильно и объяснимо.
3. **RAG** — чанки markdown с YAML-метаданными → векторный индекс (Chroma) или локальный TF-IDF.
4. **LMS-заглушка** — JSON/CSV + HTTP API на stdlib. Канон дат — только отсюда и из FAQ.
5. **LLM** — GigaChat (LangChain) → OpenAI-compatible → офлайн-синтезатор по чанкам.
6. **Гардрейлы** — повторная проверка ответа: оценки, перенос сроков, готовый код ДЗ.
7. **Аналитика** — SQLite, дашборд Plotly, markdown-отчёт.

## 3. Поток одного вопроса

```
вопрос
  → classify_scenario()
  → retrieval_query = вопрос + подсказка сценария
  → search(k=5, filters: module / resource_type / topic)
  → system prompt = роль ⊕ ограничения ⊕ уровень ⊕ сценарий ⊕ few-shot
  → human = вопрос ⊕ чанки ⊕ LMS-факты ⊕ история
  → generate()
  → scan_violations() / looks_like_full_solution()
  → adapt_answer(level)
  → QueryLogger
```

## 4. Почему так, а не «один большой промпт»

- Сценарии можно тестировать без модели.
- Few-shot не размывается: в промпт попадают близкие примеры.
- Источник истины по датам отделён от лекций: модель не «вспоминает» дедлайн из старого чанка.
- Fallback не ломает демо, если нет ключа GigaChat.

## 5. Нефункциональные рамки демо

- Нет реальных ПДн: идентификаторы вида `STU-1001`, имена сокращены.
- Куратор не пишет в LMS (read-only stub).
- Оценка качества RAG — ручная по few-shot плюс unit-тесты на ограничения.

## 6. Куда расти в проде

- Классификатор сценария моделью с JSON-схемой.
- Гибридный поиск (BM25 + вектор) и reranker.
- Human-in-the-loop для гардрейлов.
- Отдельный контур логов без текста вопроса, только темы (если появятся реальные студенты).
