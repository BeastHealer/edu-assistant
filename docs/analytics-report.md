# Аналитический отчёт: структура и регламент

Дашборд в Streamlit собирает те же поля, что и этот шаблон. Выгрузка: кнопка «Скачать отчёт Markdown».

## Поля лога (`queries`)

| Поле | Смысл |
| --- | --- |
| created_at | UTC |
| student_id / student_name | только учебные профили демо |
| question / answer | текст диалога (в проде хранить ограниченно) |
| scenario | маршрут промпта |
| level | beginner / advanced |
| module | фильтр или модуль верхнего чанка |
| topics | JSON-список тем/модулей из RAG |
| sources | doc_id и score |
| llm_backend | gigachat / offline-rag / … |
| blocked | сработал гардрейл |

## Блоки отчёта для команды курса

1. **Объём** — сколько обращений за период (нагрузка, которую сняли с людей).
2. **Сценарии** — дедлайны vs содержание vs техника.
3. **Темы** — где дыры в материалах.
4. **Повторяющиеся формулировки** — кандидаты в FAQ и в подсказки LMS.
5. **Гардрейлы** — студенты просят оценку/готовое ДЗ: усилить объявление правил.
6. **Рекомендации** — что править в контенте на следующей итерации.

## Как читать сигналы

- Пик `deadline` перед сдачей → даты в LMS недостаточно заметны.
- Пик `difficulty` на M4/M5 → добавить разбор на вебинаре, упростить абзац лекции.
- Один и тот же вопрос про ДЗ-1 → переписать методичку, не «ещё раз объяснить в чате».
- Много `constraint` → в онбординге явно написать, чего куратор не делает.

## Периодичность

Еженедельно на планёрке курса: 10 минут по отчёту. Не разбираем отдельных студентов — только агрегаты.

Демо-данные: `python scripts/seed_analytics.py` (96 вымышленных событий).
